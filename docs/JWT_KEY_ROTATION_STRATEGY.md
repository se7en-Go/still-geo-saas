## 3. 密钥轮换机制

### 3.1 多密钥支持
```yaml
密钥状态:
  Active:
    - 当前使用的密钥
    - 用于新token生成
    - 用于token验证
    - 支持多个active密钥

  Inactive:
    - 仅用于token验证
    - 不用于新token生成
    - 用于已有token过渡
    - 逐步减少使用

  Deprecated:
    - 已过期的密钥
    - 不用于任何操作
    - 保留审计记录
    - 准备删除

  Deleted:
    - 物理删除的密钥
    - 无法恢复
    - 相关token失效
    - 完全移除
```

### 3.2 密钥存储结构
```yaml
数据库设计:
  jwt_keys表:
    id: 主键
    key_id: 密钥唯一标识
    key_name: 密钥名称
    key_value: 加密存储的密钥
    algorithm: 签名算法
    status: 密钥状态 (active/inactive/deprecated)
    created_at: 创建时间
    activated_at: 激活时间
    deactivated_at: 停用时间
    expires_at: 过期时间
    created_by: 创建者
    description: 密钥描述

配置文件:
  jwt_config:
    current_key_id: 当前活跃密钥ID
    active_key_ids: 所有活跃密钥ID列表
    inactive_key_ids: 非活跃密钥ID列表
    rotation_policy: 轮换策略配置
    grace_period: 宽限期配置
```

## 4. 密钥生成和管理

### 4.1 密钥生成规范
```yaml
算法标准:
  推荐算法: HS256
  备选算法: HS384, HS512
  密钥长度:
    HS256: 256位 (32字节)
    HS384: 384位 (48字节)
    HS512: 512位 (64字节)

生成方式:
  随机数生成: CSPRNG
  编码方式: Base64URL
  前缀标识: geo_jwt_v1_
  示例: geo_jwt_v1_32VHgtlzJhor6CVRC9y9cJQs8vGqWC0p7VFsS2WwcQhETvHsHrH8SEUpy0Do7U3

强度要求:
  熵值: >256位
  重复概率: <1/2^128
  预测难度: 计算不可行
  碰撞概率: 可忽略不计
```

### 4.2 密钥存储安全
```yaml
存储加密:
  算法: AES-256-GCM
  密钥管理: KMS集成
  访问控制: 基于角色
  审计日志: 完整记录

传输安全:
  协议: TLS 1.3
  证书: 有效证书
  验证: 双向认证
  加密: 端到端

备份策略:
  频率: 每次密钥生成后
  位置: 安全存储
  加密: 多层保护
  访问: 严格限制
```

### 4.3 密钥生命周期

## 6. 宽限期管理

### 6.1 宽限期策略
```yaml
宽限期定义:
  目的: 允许现有token自然过期
  长度: 30天 (可配置)
  开始时间: 新密钥激活后
  结束时间: 旧密钥删除前

宽限期配置:
  jwt_grace_period_enabled: true
  jwt_grace_period_duration: 30d
  jwt_grace_period_warning: 7d
  jwt_grace_period_notification: 3d
```

### 6.2 宽限期处理
```yaml
Token验证逻辑:
  验证顺序:
    1. 使用当前活跃密钥验证
    2. 如果失败，使用非活跃密钥验证
    3. 如果token过期，返回过期错误
    4. 如果全部失败，返回无效错误

  记录日志:
    - 成功验证的密钥版本
    - 宽限期验证次数
    - 过期token数量
    - 异常验证尝试

用户通知:
  过期提醒:
    - 提前7天发送提醒
    - 提前3天发送警告
    - 过期当天强制重登录

  重新认证:
    - 优雅的会话过期处理
    - 保存用户工作状态
    - 提供快速重新登录
    - 记录重新认证事件
```

## 8. 应急响应

### 8.1 应急场景
```yaml
密钥泄露:
  响应时间: <5分钟
  处理流程:
    1. 立即停用可疑密钥
    2. 生成新的紧急密钥
    3. 强制所有用户重新登录
    4. 查找泄露原因
    5. 修复安全漏洞

系统故障:
  响应时间: <15分钟
  处理流程:
    1. 启用备用密钥
    2. 切换到安全模式
    3. 通知用户系统维护
    4. 修复系统问题
    5. 恢复正常运行

性能问题:
  响应时间: <30分钟
  处理流程:
    1. 监控性能指标
    2. 分析瓶颈原因
    3. 优化配置参数
    4. 扩容系统资源
    5. 验证性能恢复
```

### 8.2 回滚策略
```yaml
回滚条件:
  - 认证失败率 >5%
  - 系统可用性 <95%
  - 性能下降 >50%
  - 安全事件发生

回滚流程:
  1. 立即停止密钥轮换
  2. 恢复到上一个稳定配置
  3. 重启相关服务
  4. 验证系统正常
  5. 分析失败原因
  6. 制定改进方案
```
